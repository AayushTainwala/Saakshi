- [x] (Repair A) **Signed records are still written the old way.** Group 1 made the files that are *rewritten* safe (session.json, the markers, the key file). A signed record and its signature are written once and never again, through the file library's plain write, and are not flushed to storage. A cut-off at that moment can leave the newest record half-written; the app now ignores a record that has no signature beside it, so nothing breaks, but that last checkpoint is lost. Writing them through the same one-step write is small (the native function needs a second form that takes bytes, for the signature). **I recommend doing it in this round,** in group 3's pull request. Shall I? *Answered 14 Nov:* yes. Signed records and their signatures are written in one step, like the index. It is built with "when a recording stops by itself" ([../briefs/2026-11-14-when-a-recording-stops.md](../briefs/2026-11-14-when-a-recording-stops.md), group 3), not as a follow-up to round A. SPEC E1.
- [x] (Repair A) **A file with no signed record.** When an index is rebuilt, a file found in the recording's folder with no signed record (the app died after saving it and before signing) is listed, marked "No signed record was found for this file", and can be shared as it is. It is not signed afterwards. Signing it later would need a decision on what such a late record says (its start time is not known; only the file's last write is). **I recommend leaving it as built** until you decide that. This also covers a file whose signing failed because the key was busy. Repair round B; it needs a bundle-format change. SPEC E1.
